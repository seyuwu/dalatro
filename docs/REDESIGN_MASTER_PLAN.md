# DALATRO — Master Redesign Plan (зафиксирован 2026-09-10)

План внедрения `DALATRO_Design_Changes_Master_Document.docx` (мастер-спек редизайна).
Источник требований: спек + обсуждение. Этот документ — единственный источник правды по порядку работ.

## Принципы

1. **Контент сидит сверху на небольшом числе универсальных механик.** Никаких 100 веток в switch:
   развилки и апгрейды — это таблицы данных + ~12 примитивов эффектов.
2. **Все мутации стейта — только через `Game.dispatch()`.** Контент никогда не мутирует стейт напрямую.
3. **Баланс раньше сложности** (пRIORITY из спека): мультипликативная власть, инфляция золота,
   стакинг предметов и общее число предметов контролируются ДО добавления 100 развилок и 100 апгрейдов.
4. **Детерминизм по сиду.** Все новые броски RNG — через `Rng.current()`; забег воспроизводим.

## Что уже сделано (не переделывать)

- §3 спека: лига рангов — 14 рангов Рекрут→Папочка, наслоение `adds`, `waveHpMult` с якорями по актам,
  мутации башен, проклятия забега (Титан 100+), выбор ранга на титуле, Папочка-Трон. (`src/systems/ranks.js`)
- §2 Лагерь: реальный маршрут (+6G, +1 казарма, бесплатное увольнение).
- §1 Композиция UI: 4 зоны (topbar / sidebar / battle scene / context / bottom band),
  вердикты «БАШНЯ ПАДАЕТ» / «ГЛИФ: УРОН = 0» / «ЕЩЁ 1 УДАР».
- §6.3 частично: оверкилл-кап 5G, налоги рангов.

### Ключевые находки фаз A–D/I-mini (см. BALANCE.md §Аудит силы)

- ×-стек поверх базы: P50 ×1.9–2.9, P90 ×3.5–9, MAX ×10–32 → массовую конверсию × → +
  НЕ проводить до калибровки; конверсия аддитивом в mult-слот на низких комбо УСИЛИВАЕТ удар.
- Bloodthorn переработан по таблице: был безусловный 35% ×2.2 в 11–16% всех боёв,
  стал 50% ×2.2 только на боссах/мини-боссах (условие IS_MINIBOSS_WAVE добавлено).
- Жадный бот после коммита c63f726 (экспоненциальная HP) не побеждает ни на одном ранге:
  Рекрут P50-волна смерти 11–12, Титан — 3 (убивают glyph/mines/reflection).
  Первый кандидат I-full — калибровка кривых HP/награды, потом I-mini-таблица снова.
- Сид короче 4 символов молча считается случайным (`normalizeSeedCode` требует 4–8) —
  в тестах использовать только 4+ символьные сиды.

## Фаза A — UX / feedback фиксы

- **NORMAL-вердикт**: «ОСТАНЕТСЯ N HP» (сейчас `verdictHtml` возвращает пустую строку).
- **КРИТ!**: большой красный индикатор после боя + строка в логе. Флаг крита уже пишется в resolution
  (`triggers.js` — `ctxBase.note = "крит!"`), нужна явная отрисовка в battle scene.
- **Тултипы**: единый стилизованный поповер взамен браузерных `title=""` (атрибут `data-tip`,
  один плавающий div в ui.js; герои, предметы, товары лавки, рекруты, формации).
- **Хоткеи по фазам**: волна — Enter = бой, D = сброс; лавка — 1–5 покупка, R реролл, Enter выход;
  развилка — 1–3 выбор маршрута.
- **Шапка лавки**: следующая башня в заголовке лавки; сайдбар никогда не показывает мёртвую башню.

## Фаза B — стартовые архетипы (§7.1 спека)

- `ARCHETYPES_DATA = { id, name, emoji, quote, guaranteed: [3 героя], poolBias: attr, perk }`.
- Трио гарантировано, остальные слоты колоды набираются из тематического пула по сиду
  (например ШТУРМ — перевес AGI). Старт задаёт направление, не запирает игру.
- Перк архетипа — микроскопический (+1G старт, бесплатный первый реролл, +1 ТП в акте 1…),
  реализован как run-level список модификаторов, читаемый теми же хелперами, что ранговые `adds`.
- `START_RUN` получает `starterId`; UI — выбор архетипа на титуле рядом с рангом/режимом.

## Фаза C — лимит предметов (§6.2 спека)

- В `items.js` явное поле `slotClass: off|def|util` (не выводить из `category`).
- `Game.itemCapacity(state)`: **6 total всегда**; класс-лимиты — ранговый модификатор
  (`capClass` в `adds` с Титана: 2+2+2). Гибкость по рангам, без хардкода.
- Проверка в `BUY_ITEM`; продажа освобождает слот; UI — точки-слоты в лавке и сайдбаре
  с указанием, какой класс заблокирован и каким правилом лиги.
- Октарин (`ADD_MULT_PER_ITEM`) от лимита только выигрывает — выбор предметов становится осмысленным.

## Фаза D — аудит мультипликативной власти (§6.1 спека)

**Сначала измерение, потом решения.** НЕ предрешать конверсию × в +.

- Пайплайн: `damage = power × mult × finalMult × towerMult`; ADD_MULT пишет в `mult`,
  MULT_MULT умножает `mult`, оба затем умножаются на `finalMult` (ставка × импульс × кровь).
  Конверсия «×2.2 → +2.2 mult» может УСИЛИТЬ предмет в билдах с коммитом/импульсом.
  Точка вставки аддитива — отдельное решение (в mult / в finalMult / отдельный слой `damagePct`).
- Инструмент: структурированный `scoring.trace` рядом с human-readable steps:
  слои BASE → HERO → ITEM → COMBO → MUTATION → CRIT → FINAL, вклад каждого источника.
- Отчёт: P50 / P90 / MAX ожидаемого урона и золота по волнам/актам.
- Только после таблицы — решения по Bloodthorn (сделать ситуативным), Daedalus, Rapier и остальным.

## Фаза I-mini — бот-бейзлайн (§10 спека)

- Расширение `tests/ab.mjs` → метрики по забегам: winrate, медианная волна, медиана золота,
  число предметов, рероллы, доминирующий герой/комбо/формация, причина смерти.
- Прокси «колебания» жадного бота: зазор между выбранным и следующим-лучшим вариантом
  (маржа выбора) — ловит UI-причины слабых решений.
- Прогон: Recruit/Knight/Hero/Legend ×20, Titan ×50. Это baseline ПЕРЕД фазами E/F.
- Один инструмент с D: трассировка из D дорастает до полных метрик, не писать дважды.

## Фаза E — фреймворк развилок (§4 спека, 100 вариантов)

- `ROUTES_DATA`: `{ id, name, emoji, desc, rarity, weight, minAct, minRank, tags, effects[] }`.
- Примитивы эффектов (~12): `GOLD_DELTA`, `TOWER_MOD`, `TOWER_HP_MULT`, `REWARD_MULT`,
  `SHOP_MOD`, `HAND_MOD`, `REVEAL`, `ITEM_GIFT`, `HERO_EFFECT`, `GAMBLE`, `SKIP_WAVE`, `DELAYED_FLAG`.
- После лавки — ролл 3 карт: 2 коревых (обычная/сильная/лагерь) + 1–2 спец через веса и фильтры.
- «Боевые» развилки маппятся на существующий пайплайн модификаторов волны (тот же, что ранговые мутации).
- Ролл детерминирован сидом; маршрут живёт в стейте (сейв/лоад).
- Первая партия ~25 вариантов на все примитивы, затем добивка контентными строками.
- UI: карточки развилки с риск/наградой; описание эффекта генерируется из данных.

## Фаза F — апгрейды лавки (§5 спека, 100 вариантов)

- **Scalar-апгрейды** — агрегатор `systems/upgrades.js`: `dmgPct`, `goldPct`, `handSize`,
  `rerollDelta`, `sellPct` → считаются в одном месте, интеграция: шаг урона `resolveFight`,
  шаг золота `CONFIRM_FIGHT`, размер руки DeckSys, цена реролла Ranks, цены Economy.
- **Hook-апгрейды** — через СУЩЕСТВУЮЩУЮ триггерную систему (`Triggers.runEvent`, conditions),
  источники с `kind: "upgrade"`. Новых condition-типов — максимум 2–3 (FIRST_CARD, LAST_HIT, WAVE_STREAK).
- Редкости 60/25/10/4/1; 1–2 слота апгрейдов в лавке, цена 2–4G; не занимают слоты предметов.
- Ловушка «100 апгрейдов = 5 процентов»: hook-слой обязателен, иначе вся палитра схлопнется в цифры.

## Фаза G — XP героев (§7.2 спека)

- `run.heroXp`; XP за победные бои; пороги уровней; +1 силы за уровень, кап ~+3.
- Встраивается в `Game.rankOf` (там уже тренировка + усталость). Тренировка в лавке — платный ускоритель.
- UI: пипсы XP на карточке героя.

## Фаза H — скорборд / лидерборд (§8.1 спека)

- Формула счёта: волна × ранг × чистота забега (казармы, оверкилл, золото).
- Локальный лидерборд в localStorage: Best Score / Highest Rank / Fastest Win / No-Death.
- Запись забега: дата, сид, ранг, счёт, волна, время, смерти.

## Фаза I-full — массовый плейтест и калибровка (§10 спека)

- Массовый прогон бота по всем рангам; death-cause распределение; калибровка hpMult/goldMult рангов;
  заполнение таблицы §6.4 спека реальными замерами HP/урона/золота по волнам.

## META / LIVE OPS — вне пайплайна

- Premium: только косметика (темы, скины карт, эффекты добивания, пресеты, сезонный прогресс). Силу не продаём.
- Telegram/сообщество: башня сообщества, тег créateur, опциональная «секретка» — не блокирует прогресс.
- Код — максимум одна опциональная модалка «Сообщество» в фазе H, не раньше.

## Сквозные технические требования

1. **Версионирование сейва**: `SAVE_VERSION` + `normalizeState()` (мёрж дефолтов `createInitialState`)
   вводится в фазе C — до того, как появятся новые поля стейта (`upgrades`, `heroXp`, слоты).
2. **Недетерминизм сидов**: новые броски RNG меняют путь старых сидов. С фазы E сиды несравнимы
   между версиями — A/B-сравнения только в рамках одной версии. Пометка в BALANCE.md.
3. **Тесты**: каждая фаза добавляет кейсы в `node tests/run.js`. Развилки/апгрейды — тесты
   детерминизма ролла + по кейсу на примитив.
4. **Сборка**: `node build.js` после каждой фазы; скриншоты для VISUAL_SPEC при UI-изменениях.

## Definition of Done (из спека, сокращённо)

Вердикт боя виден до клика; рука phase-aware; лагерь реально пропускает бой; старт даёт осмысленную
вариативность; криты ПА подтверждены визуально; Zeus/CM пересчёт при движении мгновенный;
нигде нет мёртвой башни; предметы нельзя скупить все; Bloodthorn не доминирует; кривые урона и золота
замерены; сложность меняет стратегию, а не только HP.
